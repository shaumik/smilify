## On "self-updating documentation"

Mintlify's pitch is *"the knowledge platform built for agents"* — docs that
agents can read, and an agent that keeps docs updated via pull requests.
Where we honestly stand:

- **Agents reading us**: partially true today — docs are plain MDX in git
  plus a role-aware `llms.txt`. The full agent-readability layer
  (`llms-full.txt`, raw Markdown serving, MCP) is not built yet.
- **Self-updating**: true for the API reference only — it regenerates from
  the OpenAPI spec on every request, so spec changes are live instantly.
  Prose does not update itself; nothing watches the codebase and proposes
  doc changes.

<Note>
  The credible path to parity here: since docs are git-native, a CI job can
  run a coding agent (e.g. Claude Code) on merge to draft doc updates as
  PRs — the same workflow that built this platform.
</Note>
