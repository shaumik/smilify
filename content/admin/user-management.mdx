title: User management

There is no user database in this codebase. Sign-in is Descope-only, and
who can access the docs — and at what level — is managed in the Descope
console.

## Granting access

Anyone who can complete the Descope flow for this project can read the docs
as a **member**. Control the population in Descope: invite users, restrict
sign-up methods, or gate by domain — all in the console, no deploy needed.

## Granting admin

<Steps>
  <Step title="Assign a role in Descope">
    Console → **Users** → select the user → assign the `docs-admin` role
    (or any role listed in `DESCOPE_ADMIN_ROLES`).
  </Step>
  <Step title="They re-sign-in">
    Roles are read at sign-in, so the change applies on the user's next
    session. To force it immediately, have them sign out and back in.
  </Step>
</Steps>

<Info>
  `DESCOPE_ADMIN_EMAILS` (comma-separated) force-grants docs admin to
  specific emails regardless of Descope roles — useful for bootstrapping the
  first admin before roles are set up.
</Info>

## Revoking access

Disable or delete the user in Descope. Existing docs sessions expire within
7 days; rotate `SESSION_SECRET` to invalidate every outstanding session
immediately.

## Agent access

AI agents authenticate with the `DOCS_AGENT_TOKEN` bearer token, not
Descope — rotate it in the server environment. Token requests act as the
member role unless `DOCS_AGENT_ROLE=admin`.
